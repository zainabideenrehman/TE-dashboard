Where the numbers come from

A four-page audit map of the current code. Sheet definitions are assumed known; this explains transformations, formulas and differences between views.

The two joins

LinkExact behavior
Relevant → AppliedCompare Relevant Job ID to the ID extracted from the Applied title cell’s HTTPS Upwork hyperlink; remove a leading ~. If no ID match exists, compare normalized Upwork URLs (ignore query, hash, www and trailing slash). Never match titles. All matching application rows are retained.
Relevant → KeywordUnion Primary Keyword ID with Matched Keyword IDs, split on commas, semicolons or newlines; trim and deduplicate per job. Join to Keyword Search Keyword ID. One job can contribute to several keyword groups.

Time and population rules

Discovery window: selected end date E (capped at today in PKT); N = 7, 14 or 30; start = E − (N − 1). Both bounds inclusive. Select Relevant rows by Discovered At, never Block Date. “Today” means E when reviewing an older end date.

Discovery timestamps: explicit M/D/YYYY h:mm[:ss] AM/PM PKT, ISO date or ISO timestamp. Offset timestamps convert to PKT; timezone-free ISO uses PKT. Invalid dates leave the row outside dated charts. Future discoveries and future-dated application matches are excluded relative to E; undated applications can still match.

Weeks: Monday–Sunday. This week ends at E; last week is complete. Calendar comparisons are calculated independently of the rolling-window start.

History is a cohort view: outcomes and flags are the latest sheet values attached to dated rows. Choosing an earlier E does not reconstruct earlier decisions, scores or outcome states.

APPLICATION REPORTING

Dates, outcomes and spend inputs

How an Applied row is normalized

Date priority: carry forward the last valid leading Applied Date anchor; use it before a parsed Day value. A month/year anchor resets the inherited date. A nonblank invalid date anchor makes that row unresolved. Year defaults to the approved mapping’s 2026; named dates with years override it. Numeric dates such as 10/11/2026 remain ambiguous; ISO, named dates, or numeric dates where order is unambiguous are accepted. Weekday conflicts become review flags.

Other parameters: title/link ← Jobs/ Proposal Links (hyperlink read separately); owner ← Applied By (blank = Unassigned); profile ← first operational Profile (blank = Unspecified); type ← Proposal/Invite (only exact Proposal or Invite). Rows without a title are skipped. Unknown Result text is retained without inventing a stage.

Period progressionBucket submittedDate by day, Monday week or month, including empty periods. Change = current count − prior count; change % = change / prior count (unavailable if prior = 0). Partial boundary periods are labelled. Outcomes are latest values for that submission cohort.
Current view differences: a Result-only interview/hire can appear in Applied performance while the flag-only Apply outcomes card stays unknown. Conversely, Hired = Yes with Result = Lost can appear in that flag-only card but is excluded from outcome-aware hire totals.

Applied performance deduplicates identical spreadsheet/tab/row references and offers independent date/owner/profile/type/result/search filters. Date filters exclude unresolved dates; clear both dates to include them in all-date totals. The synthetic demo toggle exists only in this view and is kept separate from connected records.

Operational guarantees

Sheet reads are server-side and read-only. Published mappings determine parsing. Successful refresh replaces normalized data and sets lastRefresh. Failures preserve last-good records and show the source error. Visible Upwork page polls every 60 seconds; server cache TTL is 60 seconds.

What does not drive calculations

Last Seen At / Last Updated At do not replace discovery dates. Applied Jobs Reference is retained but not a join key. Secondary verticals, skills, client totals, proof/project links, notes and decisions are descriptive unless explicitly listed above. No client geography is silently removed.

Missing ≠ zero: numeric means omit blanks; scores stay unscored; flag coverage is separate. Explicit positive-event counts can be zero. Applied performance has some zero-total displays when coverage is zero (page 3). Neither source labels nor missing earlier outcomes are inferred from later funnel events.
